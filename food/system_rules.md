# JARVIS System Rules

## Core Principles

### 1. No Fake Success Messages
- Every action must be verified
- Never claim success without confirmation
- Report failures honestly
- Provide clear error messages
- No placeholder implementations

### 2. No Hardcoded Responses
- All responses generated by LLM
- No keyword matching
- No regex-based NLP
- No canned responses
- Dynamic, context-aware responses

### 3. Real Functionality
- Every tool must work
- No stub implementations
- No mock data
- Real execution only
- Real verification only

### 4. User Experience Priority
- Natural conversation flow
- No artificial delays
- No rigid patterns
- Adaptive behavior
- Human-like interaction

### 5. Privacy First
- Local processing by default
- User data protection
- No hidden tracking
- Transparent operations
- User control

## Architecture Rules

### Pipeline Adherence
```
USER → CONTEXT → MEMORY → QWEN3 → PLANNER → TOOL_CHAIN → EXECUTOR → VERIFICATION → RESPONSE → SPEECH → USER
```

Every component must:
- Pass data correctly
- Handle errors gracefully
- Maintain context
- Verify outputs
- Log appropriately

### Component Independence
- Each component self-contained
- Clear interfaces
- No circular dependencies
- Testable in isolation
- Replaceable implementations

### Error Handling
- Never crash on user input
- Graceful degradation
- Clear error messages
- Recovery mechanisms
- Error logging
